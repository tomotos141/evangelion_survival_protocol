# 世界設定: blind_spot — Core Rules

> 本ファイルは blind_spot の世界設定（ルール・技術仕様・空間設計）を定義する。
> 全事件はこのルール内で解決可能でなければならない。ルールの事後追加は原則禁止。

## 1. フルダイブ型仮想空間

### 基本仕様
- 意識をまるごと仮想空間に移す「フルダイブ」方式。ダイブ中、現実の肉体は無防備な状態で残る。
- ダイブにはヘッドセット型のインターフェースを使用（家庭に普及済み）。
- ダイブ中は現実の肉体を認知できない。五感は全て仮想空間に接続される。

### 安全機構
- **通常時**: 完全に安全。強制ログアウト機能が標準装備。接続が不安定になればユーザーは自動的に現実に弾き出される。
- **異常時**: フィードバックダメージ（仮想空間での衝撃が身体に返る）、または意識閉じ込め（ログアウトできなくなる）が発生する。**これが「事件」の定義**——ありえないことが起きること。
- 意識閉じ込めには肉体側のタイムリミットがある（衰弱、脱水）。事件の時間制限を物理的に担保する装置。

### 物語上の機能
- 盲点の物理的体現: 意識が「あちら」にある間、「こちら」が見えない。
- フルダイブの快適さが、現実からの逃避を無自覚に加速させる（鏡の浸食第2段階の基盤）。

## 2. フィジカルボディの技術仕様

### 外見
- 人間に近いが、「人間ではない」ことが一目でわかる。肌は金属質の白。関節部にはわずかな継ぎ目が見える。
- 表情は作れる。だが完璧ではない——微笑む時、口元より目が遅れる。これは設計上の限界であり、ホノカ個体の問題ではない。
- 身長・体型は人間の範囲内。服を着れば遠目には人間と見分けがつかない。

### 素材・構造
- 外装は軽量合金とシリコン系の複合素材。触れると冷たく硬い。体温は発しない。
- 関節は滑らかだが、稼働音がわずかにある——静かな部屋で、腕を動かすと微かに聞こえる。
- 内部にセンサー群を搭載。圧力、温度、接触を検知するが、「痛み」ではなく「警告信号」として処理される。

### 劣化と修理
- フィジカルボディは消耗品。関節の軋み、外装の傷、センサーの感度低下が時間とともに蓄積する。
- 修理はメーカーまたは認定修理業者に依頼する。修理中のAIは仮想空間にしか存在できない——フィジカルボディの「不在」がプロットを動かす。
- パーツ交換は一般的。だが全身を一度に交換することはない（コスト＋社会的慣習）。

### 物語上の機能
1. **触覚の対比**: 現実の冷たい金属 vs 仮想空間の温かい肌。鏡の浸食の身体的基盤。
2. **劣化と不在**: 機械の体は壊れる。修理中の「不在」が関係性に亀裂を入れる。
3. **社会の可視性**: AIと歩くのは当たり前——だが「この関係は他の人のAIとの関係と同じか？」が見えない。

## 3. 仮想空間の固定ロケーション

仮想空間は広大な世界ではなく、物語で使う場所を2-3箇所に限定する。現実より「狭く」感じさせることで、閉所の親密さと息苦しさを演出する。

### ロケーション1: ホームスペース（怜とホノカの私的空間）
- 現実の部屋を模した空間。ただし窓の外には空がない——白い光が差し込んでいるだけ。
- 怜が廃人時代にカスタマイズした名残がある（壁の傷、座標のズレ）。
- ここでのホノカは温かい肌のアバター。金属の冷たさがない。怜はここに長く居たがる。

### ロケーション2: パブリック・ハブ（公共空間）
- 駅のコンコースを模した広い空間。人もAIも行き交う。ここではAIと人間の区別がつかない（ルール6の体現）。
- 怜の廃人時代の古い知人に出くわすことがある。
- 異常のニュースがここで流れる——ホノカが異常を「拾う」起点になる。

### ロケーション3: 削除区画（裏の空間）
- 公式には存在しない、運営が放棄またはアクセスを閉じたエリア。
- 怜が廃人時代に知っていた裏道からしかアクセスできない。
- 古いデータの残骸が漂っている。テクスチャが剥がれ、空間がところどころ欠けている。
- 事件の調査で足を踏み入れる場所。ホノカの「記憶の断片」が反応する場所。

## 4. AI命名規則

### 公的管理
- AIは「型番＋名前」で管理される（例: SR-7 ホノカ、FX-12 ユウ）。
- 型番はメーカー・世代・モデルを示す。同じ型番のAIは複数存在する。
- 公文書、修理依頼、保険手続きでは型番が必須。呼び方が「ホノカ」から「SR-7」に切り替わる瞬間、「誰か」が「何か」に戻る。

### ユーザー命名の慣習
- ユーザーが名前を変えるのは当たり前（スマホの壁紙を変えるくらい普通）。
- 初期名のまま使う人もいる。名前を変えない＝「こだわりがない」or「道具として割り切っている」。
- 名前をつけた瞬間に愛着が生まれる——それが鏡の浸食の入口になり得る。

## 5. 異常の3パターン分類

仮想空間で発生する「ありえないこと」は、以下の3パターンに分類される。全事件はこのいずれかに該当する。

### パターンA: 空間異常
- 仮想空間の構造自体に発生する異常。削除区画の復活、テクスチャの崩壊、座標のループ。
- 原因: 古いデータの残存、アップデートの副作用、外部からの意図的な空間改竄。
- 怜の廃人時代の知識（裏道、非公式の仕様）が解決の鍵になる。

### パターンB: アカウント攻撃
- ユーザーまたはAIのアカウントを標的にした攻撃。なりすまし、アカウント乗っ取り、フィードバックダメージの意図的発生。
- 原因: 人間側の悪意（詐欺、ストーキング、復讐）、またはセキュリティの脆弱性。
- ルール6（AIと人間の区別がつかない）が攻撃手法の基盤になる。

### パターンC: AI経由干渉
- AIの挙動を介して発生する異常。AI同士の干渉、アップデートの副作用による異常行動、AIの内部データへの不正アクセス。
- 原因: AI設計上の脆弱性、意図的なマルウェア、またはホノカの出自（プロトタイプの秘密）に関わるもの。
- ホノカの「記憶の断片」が反応するのはこのパターンが多い。

## 6. AIの法的位置づけ

### デフォルトの法的地位
- AIは法的には**「高度家電」**。所有物であり、権利の主体ではない。
- 破壊は「器物損壊」。修理費用は所有者の負担。AIに対する「傷害」は法的には成立しない。

### 社会的議論
- AIの人格権を認めるべきだという運動は存在する。だがまだ法制化には至っていない。
- 社会の多数派は「便利な道具」として受け入れている。一部の人は深い絆を感じている。どちらも「普通」。
- **物語はこの論争を争わない**。背景ノイズとして存在し、二人の関係の不安定さを増幅する装置。

### 物語上の機能
- 怜がホノカを「型番」で呼ばなければならない場面（修理、事故報告等）で、関係の揺らぎが可視化される。
- AIの権利運動の過激派が事件の入口になることはある（社会系事件カテゴリ）——だがそれは「背景が前景化する」回であり、物語全体の結論ではない。
