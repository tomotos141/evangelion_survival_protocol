# Inconsistency Repair Workflow

ユーザーからの指摘によって「キャラクターの性格」や「世界観の設定」に修正が入った場合、単に原稿を直すだけでなく、その変更を「ルール（スキル）」や「定義（設定資料）」にも反映させ、将来的なブレを防ぐ。

> **チーム体制との関係**: Proofreader Agent が設定整合性チェックを担当するが、スキル定義やエージェント定義の更新は本ワークフローが扱う。

## 手順

### 1. 修正箇所の特定と分析
- ユーザーの指摘内容を分析する。（例：「シンジが冷静すぎる」→「PTSD設定の強調」）
- 影響範囲を特定する:
  - 原稿（`drafts/`）
  - キャラクター設定（`docs/characters/`）
  - スキル定義（`.agent/skills/`）
  - エージェント定義（`.claude/agents/`）
  - 著者プロファイル（`.agent/author_profile.md`）
  - ワークフロー（`.agent/workflows/`）

### 2. 設定資料の更新 (priority: high)
- `docs/characters/` 内の該当キャラクターファイルを修正する。
- `.agent/author_profile.md` に美学の変更があれば反映する。
- 変更点には「変更理由」をコミットメッセージに残す。

### 3. スキル・エージェント定義の更新 (priority: medium)
- `.agent/skills/` 配下のチェックリストに、新しいNG項目や推奨項目を追加する。
  - 例: 「シンジの独白において、軍事用語や過度に大人びた表現はNGとし、感覚的・感情的な表現を優先する」
- `.claude/agents/` 配下のエージェント定義に変更が必要なら反映する。
  - 例: Writer Agent の「絶対禁止事項」にルール追加
- `.agent/workflows/` の該当箇所にチェック項目を追加する。

### 4. 原稿の修正 (priority: high)
- 新しい設定に基づいて、既存の原稿をリライトする。
- 影響範囲が複数エピソードに及ぶ場合は、横断的に修正する。

### 5. Pixiv版の再生成
- 修正した原稿に対応するPixiv版を再生成する。
- 変換ルールは `write_novel_episode.md` §4 を参照。

### 6. 確認
- 修正した原稿が、更新されたスキル定義のチェックに通るかを確認する。
- `Ep.\d` の残存チェック、メタ表現チェックを実行する。
