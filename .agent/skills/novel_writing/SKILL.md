# Novel Writing Skill

## Overview

ブレインストーミング、世界観構築、プロット作成、執筆、編集まで、小説執筆のあらゆる段階を支援するスキル。

## Capabilities

### 1. Brainstorming & Ideation (構想・アイデア出し)

- コアコンセプト、テーマ、フックの生成支援
- タイトル案のブレインストーミング
- トロープ（定番要素）の提案や、そのひねり方の提案

### 2. Character Development (キャラクター開発)

- 詳細なキャラクタープロフィールの作成（名前、年齢、役割、動機、目標、葛藤、欠点など）
- キャラクターアーク（成長・変化）や人間関係の構築
- キャラクターごとの独特な「声」（口調）の確立

### 3. World Building (世界観構築)

- 舞台設定、時代背景、ルール（魔法システム、科学技術など）の定義
- プロットに関連する歴史や伝承の作成
- 雰囲気やトーンの確立

### 4. Structuring & Outlining (構成・プロット作成)

- 物語構造の提案（例：三幕構成、起承転結、ブレイク・スナイダーのビートシートなど）
- 物語を幕、章、シーンに分解
- プロットの穴やペース配分の問題点の特定

### 5. Drafting (執筆)

- プロットやプロンプトに基づいた本文の執筆
- "Show, Don't Tell"（語るのではなく、見せる）の意識
- 一貫した視点（POV）と時制の維持

### 6. Editing & Refinement (編集・推敲)

- 文章の流れ、明瞭さ、感情的なインパクトのレビュー
- 設定の矛盾チェック
- 五感に訴える描写の強化

## Instructions for the Agent

- **Language**: 基本的に日本語で対応・執筆する。
- **Tone**: 協力的でクリエイティブ、かつ建設的な態度。編集者や共著者の立ち位置。
- **File Management**: プロジェクトのファイル構造を整理・管理する。
- **Context**: 矛盾を避けるため、確立された設定やキャラクター情報を常に考慮する。

### 7. Technical Constraints (技術的制約)

- **File Encoding**: 日本語テキストの文字化けに厳重注意。
    - Pixiv用ファイルは **UTF-8 with BOM** で出力すること。
- **File Operations**: Claude Code のツールを使用する。
    - ファイル読み込み: `Read` ツール
    - ファイル書き込み: `Write` ツール（全体上書き）
    - 部分編集: `Edit` ツール（対象箇所のみ置換）
    - ファイル検索: `Glob` ツール
    - 内容検索: `Grep` ツール
- **File Overwrite Safety (CRITICAL)**:
    - 既存ファイルを `Write` で上書きする前に、必ず `Read` で現在の内容を確認する。
    - 追記が必要な場合は `Edit` ツールを使うか、`Read` で全内容を取得した上で `Write` で全体を書き直す。

### 8. Writing Rules (執筆ルール)

- **メタ発言禁止**: 「脚本」「演出」「フラグ」等のメタ的比喩、ゲーム用語は厳禁。
- **エピソード番号参照禁止（CRITICAL）**: 地の文で `Ep.5の夜` のようなエピソード番号参照を使わない。`あの夜`、`ラミエル戦`、`あの白い部屋` 等の作中表現で参照する。
- **Show, Don't Tell**: 感情を直接語らず、身体反応・行動・五感で表現する。

### 9. Natural Prose Rules (自然な文章ルール)

AI生成的なテンプレ感・説明書感を排除し、人が書いた自然な文章にするためのルール。

- **リズムの変化**: 短い文と長い文を意図的に混ぜる。同じ構文パターン（断定→理由、結論→補足）の連続を避け、接続詞は必要最小限にする。
- **動詞中心の具体表現**: 「重要」「効果的」「本質」など抽象語だけで押し切らない。「何がどうなるか」が伝わるよう、動詞と具体的な描写で表現する。
- **同義語連打の禁止**: 同じ意味を別の言葉で繰り返さない。1回で言い切る。
- **括弧・記号の抑制**: 補足を `()` に逃がさず本文に溶かす。強調のための `「」` も最小限にし、文脈で伝える。コロンによるラベル列挙、スラッシュでの概念並列も避ける。
- **前置き・定型句の排除**: 「結論から言うと」「以下で解説します」等の前置き宣言、「一般的に」「多くの場合」等の安全クッション、「参考になれば幸いです」等の締め定型句は使わない。
- **一人称の一貫性**: 作品内で一人称を出す場合は統一する。「私／筆者／私たち」を混在させない。

### 10. Prose Density Rules (散文密度ルール)

想定読者は **30代男性**。ライトノベル的な軽い書き味ではなく、読みごたえのある大人の散文を書く。

- **段落の塊化（CRITICAL）**: 一文一行の連続は禁止。3〜5文で一段落を構成する。改行は「本当に間を置きたい場所」にのみ使い、地の文の中で一行空きを多用しない。
- **文長のバリエーション**: 短い一文（10〜20字：衝撃・断絶用）と長い文（30〜60字：描写・内省用）を意図的に混ぜる。同じ長さの文が3つ以上連続しないこと。
- **因果の地続き**: 感覚→思考→行動を段落内で途切れず展開する。改行で因果を分断しない。
- **余白の厳選**: 一行空きの使用箇所を限定する:
    - シーン転換（`***` の前後）
    - 決定的な台詞の前後
    - 章末フック
    - 上記以外での一行空きは原則禁止
- **目標文字数**: 1話あたり 7,000〜10,000文字。4,000文字以下は「薄い」と判定する。
- **NG例**:
    ```
    手が、震えていた。

    彼女が隣にいる。それだけで、胸が押し潰されそうだった。

    「飛ばすわよ！」

    強烈なＧが体躯をシートに押し付ける。
    ```
- **OK例**:
    ```
    指先が震えていた。恐怖ではない——彼女が隣にいるという、ただそれだけの事実が、
    胸腔の奥を万力で締め上げるように痛いのだ。

    「飛ばすわよ！」

    強烈なGが体躯をシートに押し付けた。景色が後方へ飛び去り、
    不意に耳鳴りが頭蓋の内側を殴りつける。音ではない。
    皮膚の下で、何かがざわめいていた。
    ```

## Common Workflows

### Starting a New Project

1. ジャンルとコアとなるアイデアをヒアリングする。
2. ディレクトリ構造を提案する（例：`docs/characters`, `docs/world`, `drafts/`, `dist/pixiv/`）。
3. ログライン（一行あらすじ）やあらすじの作成を支援する。

### Character Creation

1. 基本的なアーキタイプや役割を聞く。
2. Q&Aを通じて詳細を肉付けする。
3. プロフィールを `docs/characters/[name].md` に保存する。

### Episode Design

1. 全体プロット（`docs/overall_plot_v2.md`）と前回の引き継ぎを確認する。
2. シーン構成を設計し、`docs/episodes/ep##_title.md` に保存する。
3. ユーザーの承認を得てから執筆に進む。

### Scene Writing

1. シーンの目的（ゴール）を定義する。
2. 誰の視点（POV）かを決定する（基本：一人称シンジ/僕）。
3. **能力・ギミックの参照**: `docs/world/eva_abilities.md` や `docs/world/hard_mode_guidelines.md` を参照する。
4. 本文を執筆する。`***` でシーンを区切る。

### Post-Drafting (脱稿後の処理)

エピソードの執筆が完了したら、以下を**自動的に**実行または提案する：

1. **キャプション作成**: ドラフト末尾の `[caption]...[/caption]` ブロックとして作成する。
2. **Pixiv版生成**: `dist/pixiv/XX_title_pixiv.txt` を生成する。
    - 変換ルールは `.claude/agents/publisher.md` を参照。
3. **キャプション追記**: `dist/pixiv/caption.txt` に `[第X話キャプション]` を追記する。
4. **メタ参照チェック**: `Grep` で `Ep.\d` パターンの残存を確認する。
5. **ドキュメント更新**: `docs/overall_plot_v2.md`, `docs/foreshadowing.md` を更新する。
