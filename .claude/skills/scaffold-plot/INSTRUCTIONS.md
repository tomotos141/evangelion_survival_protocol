# 全体プロット生成スキル

デザインドキュメントの幕構成を入力として、全体プロットドキュメントを生成する。

## 入力

- **design_doc**: デザインドキュメントのパス
- **project_path**: プロジェクトパス（例: `projects/battousai`）
- **story_profile**: Story Profile のパス（`.agent/profiles/{project}.md`）——構造設計原則を参照

## 出力

- `{project_path}/docs/overall_plot.md`

## 手順

1. デザインドキュメントの §6（幕構成）、§8（構造設計原則）を `Read` で確認する
2. Story Profile を `Read` で確認する（構造設計原則の整合性チェック用）
3. 以下の構成で全体プロットドキュメントを作成する

### ドキュメント構成

```markdown
# Overall Plot: [タイトル]（[読み]）

## ログライン
（デザインドキュメントより転記）

## 設計原則
（デザインドキュメント §8 の構造設計原則を転記・再構成）

## 幕構成

### 第一幕「[幕タイトル]」（第X話〜第Y話）
**主題**: （この幕の中心テーマ）

#### 第X話「[話タイトル]」
- **視点**: 視点キャラクター
- **目的**: この話が全体構造の中で果たす機能
- **シーン構成**: 3〜4シーンの概要（各1〜2行）
- **伏線の仕込み**: この話で仕込む伏線のリスト
- **円環要素**: 第1話/最終話で対になる要素（該当する場合）
- **侵食/代償**: 代償の進行状況（該当する場合）

（以下、各話同様の粒度で）
```

## 作成ルール

- 各話の「シーン構成」は概要レベル（各シーン1〜2行）でよい。詳細シーン設計は `docs/episodes/` のエピソードデザインで行う
- デザインドキュメントの幕構成テーブルを展開し、各話に「目的」「伏線の仕込み」を追加する
- 話数は `第X話` 形式で表記する。`Ep.X` 形式は使わない
- 各話の概要に、前話からの引き継ぎ情報（感情状態、身体状態）を含める
- 設計原則は、Writer が各話の執筆時に参照するチェックリストとして機能するよう構成する

## 検証

- 全話がカバーされていることを確認する
- 幕ごとの主題が Story Profile のテーマ（§3）と整合していることを確認する
- `Grep` で `Ep.\d` パターンの残存を確認する
